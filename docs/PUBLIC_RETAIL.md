# UCI 공개 거래 자료 적용

출처: Chen, D. (2012). *Online Retail II*. UCI Machine Learning Repository, DOI [10.24432/C5CG6D](https://doi.org/10.24432/C5CG6D). [UCI 공식 페이지](https://archive.ics.uci.edu/dataset/502/online+retail+ii), [CC BY 4.0](https://creativecommons.org/licenses/by/4.0/). 출처를 표기하고 다음 변환 사실을 함께 기록한다.

합성 개발과 별도의 공개 실측 거래 평가다. 오로라월드 데이터나 잠재 수요가 아니다. 원본 ZIP·Excel은 코드 폴더 밖에 보존한다. 고객 ID·상품 설명·개별 invoice ID는 가공 입력/결과에 내보내지 않는다. 별도 공개 거래 계약으로 CLI와 로컬 웹에서 계산한다. Pages는 미리 계산한 공개 집계만 표시한다. Supabase 연결 코드·원격 승인 대기 상태는 [FULLSTACK.md](FULLSTACK.md)를 따른다.

## 취득·가공·실행

기존 합성 앱과 새 평가 계산부는 표준 라이브러리로 실행한다. **Excel 변환에만** openpyxl이 필요하다. Python 3.11 이상에서 선택 의존성을 설치한다.

```sh
python3 -m pip install -e '.[retail]'
PYTHONPATH=src python3 -m aurora.public_retail acquire --dest '../04_데이터/원본/공개연구데이터/UCI_Online_Retail_II'
PYTHONPATH=src python3 -m aurora.public_retail prepare --raw '../04_데이터/원본/공개연구데이터/UCI_Online_Retail_II' --output '../04_데이터/가공/2026-10-26_UCI_Online_Retail_II/weekly.json'
PYTHONPATH=src python3 -m aurora.public_retail evaluate --input '../04_데이터/가공/2026-10-26_UCI_Online_Retail_II/weekly.json' --output results/public_retail
```

취득 명령은 공식 URL과 최초 확인한 ZIP 해시를 고정하고, 60 MiB 다운로드/압축 해제 한도를 검사한다. 다른 내용이면 덮어쓰지 않고 실패한다. 이 해시는 이번 공식 다운로드의 식별자이며 게시자가 별도 서명한 체크섬이라는 뜻은 아니다. 원본/가공 데이터는 Git에 포함하지 않는다. CI는 작은 수제 입력으로 검사하며 매번 44 MB를 다운로드하지 않는다.

## 거래 집계 규칙

- 원본 1,067,371행을 두 시트에서 순차 읽는다. **2009–2010 시트에 겹쳐 있는 2010-12-01 이후 22,523행은 제외**하고 2010–2011 시트를 사용한다. 시트 안의 반복 invoice 줄은 정당한 반복 거래인지 알 수 없어 임의 삭제하지 않는다.
- 시작/마지막 불완전 주를 제외한 월요일 기준 **2009-12-07~2011-11-28, 104주**를 사용한다. 영국 거래·정상 품목 코드(숫자 5자리+선택적 문자 접미사)·양수 가격의 유효 수량을 대상으로 한다. 우편/수수료 등의 비품목 코드는 제외한다.
- 양수 정상 청구 수량을 예측 타깃 `positive_invoice_quantity`로 둔다. 취소 invoice 또는 음수 수량은 `cancellations`로 별도 집계한다. 이는 실물 반품 입고의 확인 자료가 아니며 수요에서 차감하거나 재고 입고로 사용하지 않는다.
- 첫 관측 판매 이전은 null/`not_started`로 둔다. 이는 실제 출시일이 아닌 관측 시작의 대용 표시다. 이후 거래 없는 주의 0은 전체 거래 기록에 대한 가정 아래 **기록 판매 0**이며 잠재 수요 0·품절 없음의 증거가 아니다. 품절은 null, 조달원가도 null로 유지한다. GBP 판매가격을 조달원가나 KRW 금액으로 전용하지 않는다.
- 첫 **68주**의 양수 청구 수량만으로 상위 100 SKU를 선정한다. 거래량 상위 표본이므로 전체 품목 대표 표본으로 주장하지 않는다. 동일 절단점의 과거 검증 구간으로 6개 기존 후보 중 모델을 고르고 고정한다.

## 장기 예측·재고 평가

첫 68주 뒤 4주는 워밍업, 다음 **32주(2011-04-25~2011-11-28)**를 평가한다. 예측은 매주 직전까지 관측한 판매량만 반영하는 1주 rolling 방식이며, 선택 모델과 버퍼는 시작 전에 고정한다. 마지막 4주 fixed-origin 데모 점수와 다른 평가다. 매 원점 MASE 분모는 그 이전 52주 차분으로만 계산한다. 공통 SKU·주 교집합의 점수와 모델별 coverage를 나눠 남긴다.

`inventory.py`의 순서는 입고→당시 정보로 발주→현재 시나리오 수요 충족/손실→마감이다. `initial_pipeline`의 잔여 도착 주·수량을 반영하고 주별 보유·미입고 수지를 검사한다. 기본 grid는 lead 2주/과거 평균 초기재고, lead 2주/초기재고 0, lead 4주/과거 평균 초기재고다. 각 grid에서 Naive/선택×버퍼 유무의 네 셀에 동일 판매 경로·초기 조건을 적용한다. 예측과 정책을 분리하며, 버퍼는 과거 보호기간 오차의 95% 경험 분위수(기본 3표본)라 서비스 보장이 아니다.

워밍업은 상태 전이에서 유지하고 점수에서만 뺀다. 평가 종료 시 미입고를 잔량으로 보존하고 가상 청산 수익을 넣지 않는다. 원본 판매 경로를 가상 수요로 고정한 **조건부 재생 실험**이다. 다른 재고 정책에 따른 실제 판매 반응·잠재 수요 복원·인과적 정책 평가가 아니다. 랜덤 생성은 없고 Monte Carlo 신뢰구간을 만들지 않는다. 독립 궤적 반복·확률 보정은 후속이다.

## 품목별 정책·비용 입력

`--policy-inputs`로 SKU를 키로 하는 JSON을 줄 수 있다. 기본 실험에는 원가/비용이 없어 금액은 null이다. 아래 수치는 **기능 검증용 가정**이며 UCI에서 취득한 비용이 아니다.

```json
{
  "UCI-23166": {
    "policy": {
      "currency": "GBP", "unit_cost": 1.0,
      "holding_cost_per_unit_week": 0.005,
      "shortage_cost_per_unit": 0.25, "fixed_order_cost": 2.0,
      "moq": 12, "max_order_quantity": 2400
    },
    "initial_stock": 200,
    "initial_pipeline": [{"due": 1, "quantity": 120}]
  }
}
```

통화 없이 금액을 넣거나 음수·NaN·잘못된 리드타임·발주 단위를 쓰면 거부한다. MOQ의 배수이면서 주문 용량 이하로 발주하고 부족량을 기록한다. lead_time은 grid가 소유한다. 품목 초기재고는 history grid에 적용하며 zero grid는 초기 보유 0으로 재설정하는 민감도다. 미입고 발주는 세 grid에서 해당 입력을 유지한다. 서로 다른 통화의 금액을 자동 합산/환산하지 않는다. 재고투자 값은 보유+미입고의 평가기간 평균×입력 원가이며 현금 흐름과 다르다. 보유/부족/고정 주문비용 세 항목이 모두 주어진 경우에만 총비용·음수 비용 보상을 계산한다. 일부 비용 누락을 0으로 채우지 않는다.

## 출력과 현재 결과

- `result.json`: 출처·코드/데이터/정책 해시, 분할·배정·coverage·비교·상태 전이·제외 사유.
- `forecast.csv`: 실제·예측·MASE 분모. `inventory.csv`: 수량/서비스의 공통 셀 요약.
- `decisions.csv`: episode/decision 식별자, 정보 기준시점·정책 해시·기간·발주·입고·보유/미입고·손실·비용/통화. 행동 확률은 미관측이므로 비워 둔다.
- `report.md`, `artifacts.json`: 동일 결과의 보고와 파일별 SHA-256. 생성 파일은 `results/`에 두어 Git에서 제외한다. 로컬 웹은 5개 파일 다운로드에 연결했다. 인증 서버의 서명 다운로드 코드는 구현했으며 새 마이그레이션 적용·실서비스 검증은 승인 대기다.

실제 공통 평가 **99 SKU·3,146개 SKU/주**에서 Naive MAE **178.269**, 계절 Naive **244.628**, 검증 선택 **182.500**이다. 선택 모델이 Naive보다 약 2.4% 나빴다. 평가 결과에 맞춰 모델 선택 규칙을 바꾸지 않았으며 개선으로 표시하지 않는다. 기록 판매가 있는 공통 재고 99 SKU에서 lead2/history 버퍼 정책의 총수량 충족률은 Naive 93.13%, 선택 89.80%로 둘 다 예시 목표 95%에 못 미쳤다. 재고 수량 감소만으로 절감 성공을 주장하지 않는다.

## 검사와 남은 작업

12개 신규 검사는 시트 중복·완전 주·취소 분리·품목/국가/가격 필터·미관측/원가/품절 처리·보류 미사용·재현성·CSV 일치·장기 수지·워밍업·미입고·MOQ/용량·비용 손계산을 확인한다. 연결 검사 5개와 기존 28개를 합해 Python 45개이며 JS 9개·SQL/RLS 45개도 검사한다.

U09의 긴 결정적 재생/민감도, U10의 품목별 상태·정책/비용 계약, U15의 로컬 CSV·보고·로그를 보강했다. 로컬 웹 실제 계산·Pages 저장 결과와 Supabase 실행 코드를 연결했다. 원격 SQL 적용·등록·실서비스 검증은 승인 대기이며, U05 업로드·U07 독립 보정·기업 조달원가/재고/품절·서버 검수·재학습은 남아 있다. 의류 sewing pattern 후보는 원천을 확인했으나 봉제완구 승인 부위와 도메인이 다르고 데이터셋 조건/규모의 추가 대조가 필요해 이번 분류 학습에 사용하지 않았다.
