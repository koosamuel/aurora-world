# U23 승인 샘플·패턴·조각·자재/BOM 연결

로컬 Python 서버와 두 번째 탭에 **합성 수동 대응**을 추가했다. 현재 유효한 U22 디지털 승인을 패턴/BOM 묶음에 연결한다. 자동 패턴 생성·AI 이미지의 봉제 복원·실물 적합성·기업/제작 승인·ERP 쓰기는 구현하지 않았다.

## 실행·화면

`PYTHONPATH=src python3 -m aurora serve --port 8765` 실행 후 **디지털 샘플링·라벨링 → 승인 샘플에서 패턴·BOM으로**에서 확인한다. U22에서 최신 명세 샘플의 검토/가상 승인을 먼저 완료하고, U23의 가상 작성자 역할·제품·최신 묶음·수동 연결 사유를 선택한다. 역할은 U22와 같은 고정 합성 세션이다. 누구나 선택할 수 있어 실제 인증/기업 승인 권한을 대신하지 않는다.

제품별 승인 샘플 → 패턴 → 조각·자재/BOM 흐름, 조각 윤곽/ID·부위 ID·치수·자재·pcs 수량·원단 면적, 연결 이력·변경 영향·JSON/SVG 다운로드를 제공한다. Pages는 저장된 합성 이력을 읽고 파일 크기/SHA-256을 확인하며 저장 요청을 보내지 않는다. 현재 승인 없는 제품도 패턴 자료를 조회할 수 있지만 새 연결은 거부한다.

## 데이터와 감사

기존 `2026-10-26_가상데이터_v1`의 합성 PAT 6디자인/72조각 ID·SVG를 선택했다. 같은 윤곽이 여러 ID에 쓰여 SVG는42개다. `SYN-*` 샘플과 `DESIGN-*` 패턴의 대응은 **프로그램으로 정한 임시 수동 합성 매핑**이다. 같은 동물/외형의 맞는 패턴을 검증한 결과가 아니며 원본 PAT/라벨·U21 생성 파일은 바꾸지 않는다. 부위 ID도 기업 승인 마스터가 아니다.

제품별 두 패턴/BOM 버전, 총12묶음/144조각 행을 준비했다. v2는 원단 면적 단위를 mm²→cm²로 명시 변환하고 배 패치의 자재·수량을 바꾼다. 배 패치용 자재명/면적 관리 마스터는 별도 합성 가정이며 실물 원단 물성/공급사 마스터가 아니다. 원본 BOM의 타원 근사 면적 대신 원본 조각의 다각형 면적×수량을 사용한다. 두 근사 기준을 혼합하지 않으며 출처 파일 해시·면적 정의를 기록한다.

검사 항목은 중복 조각/자재/BOM 키, 조각↔BOM의 일대일 대응, 미등록/미사용 자재, 패턴 버전, 양의 정수 pcs, 지원 면적 단위(mm²/cm²), 자재 단위 일치, 조각/재단 수량·면적 수지다. 저장 시 실제 제한 SVG의 크기/해시·다각형 면적/경계 치수도 확인한다. 감사 실패 시 연결을 만들지 않는다. 면적은 시접·재단 로스·네스팅·원단 폭·충전재·부자재·공임을 포함하지 않는 **윤곽 이론 면적**이다. 실제 소요량·원가·절감 효과로 해석하지 않는다.

## 불변 연결과 무효화

`pattern_links.py`는 승인 샘플 수정본 SHA·승인 사건 SHA·U20 명세 SHA, 패턴/BOM 버전·파일 SHA·조각/자재 행 전체·사유/합성 작성자·시각·이전 연결 SHA를 SQLite에 저장한다. UPDATE/DELETE는 트리거로 거부하고 읽을 때 해시/부모 연결을 검사한다. 해시 연결은 손상/일관성 검사이며 전자서명은 아니다.

현재 유효성은 최신 U22 활성 승인/샘플과 최신 패턴/BOM 묶음을 매번 비교한다. 승인 철회·새 샘플·새 U20 명세·새 패턴/BOM·동일 버전 파일 손상/교체는 이전 연결을 재확인 상태로 만든다. 옛 이력은 남긴다. 재승인/패턴 변경 후 새 연결은 이전과의 추가·제거·변경 조각/필드 및 자재별 면적 차이를 기록한다. 이미 연결한 동일 묶음 버전의 내용만 바꾼 재등록은 거부하며 새 버전이 필요하다. 현재 유효한 동일 연결을 사유만 바꿔 중복 저장하지 않는다.

쓰기와 일관된 조회는 U20→U22→U23 순서로 잠근다. `expected_review_seq`·승인/수정본 SHA·부모 연결 버전으로 경쟁 변경을 검사한다. 같은 역할/요청 키 재전송은 중복 저장하지 않고 **현재** 유효성을 다시 계산한다. 오래된 응답을 재사용해 승인을 되살리지 않는다. 라이브 패턴 편집/업로드 API는 없으며 버전이 있는 검증된 라이브러리 파일을 배포한다.

## API·보관

| 경로 | 역할 |
|---|---|
| GET `/api/pattern-links/catalog` | 6제품 승인/연결 요약·묶음 버전/해시·감사 |
| GET `/api/pattern-links/products/{product_id}` | 현재 승인·연결 전체 이력/유효성 |
| GET `/api/pattern-links/bundles/{product_id}/{version}` | 선택 묶음과 감사 결과 |
| POST `/api/pattern-links/links` | U22 Bearer 합성 작성자 세션, 승인/명세/패턴 고정 연결 |
| GET `/api/pattern-links/assets/{sha256.svg}` | 실제 연결에 고정한 합성 조각만 해시 확인 후 제공 |
| GET `/api/pattern-links/export/{product_id}` | 연결 이력과 고정 조각 파일 검증 후 JSON |

Host/Origin은 기존 loopback 제한을 따르며 쿼리·중복 JSON 키·비유한 값·미허용 필드를 거부한다. 잘못된 감사400, 역할403, 낡은 승인/버전·동시 변경·요청 키 충돌409다. `results/pattern-links.sqlite3`·`results/pattern-link-assets/`는 Git 제외 로컬 저장소다. 공개 예제는 `client/demo/pattern-links/`이며 세션/토큰·회사 자료를 포함하지 않는다. 기존 Supabase DEM SQL/권한/서버 실행은 변경하지 않았다. DS 원격 저장·실제 Auth/RLS·기업 자재 마스터/봉제 검증·U24 실제 효과는 후속이다. 합성 측정/보고 경로는 [별도 계약](SAMPLING_EFFECTS.md)으로 구현했다.

## 재현

```sh
# 둘 다 새 출력 경로 사용; 원본/기존 저장 결과 보존
PYTHONPATH=src python3 tools/build_pattern_library.py --source '../04_데이터/가공/2026-10-26_가상데이터_v1' --output results/new-pattern-library
PYTHONPATH=src python3 tools/build_pattern_demo.py --output results/new-pattern-demo
PYTHONPATH=src python3 -m unittest discover -s tests -p 'test_pattern_links.py' -v
```

저장 데모 생성 도구는 검증한 **자체 U22 합성 fixture만** 임시 DB에 가져와 실제 U23 연결 전이를 실행한다. 승인 가져오기 기능은 HTTP에 노출하지 않는다. 기존 U22와 같은 토끼/젖소의 현재 승인2건·연결4버전, 나머지4제품의 미승인/보류, 감사 반례8건을 보존한다. 판정/대응은 프로그램의 합성 시나리오이며 사람/기업의 승인 실적이 아니다.
